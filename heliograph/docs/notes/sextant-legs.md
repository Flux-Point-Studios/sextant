# Sextant verification legs — the claims heliograph proves in-guest

Authority: `D:/fluxPoint/sextant` @ `3a68b2f` (2026-07-14). Sextant is upstream; nothing here is re-derived — every claim cites file:line. Sextant is sans-io (no sockets, threads, or clock in `src/`; README.md:56), which is exactly the shape a zkVM guest needs: bytes in, verdict out, all trust anchors explicit inputs.

The crate's constitution (README.md:17-18): a provider supplies **bytes, never a verdict**; a hostile input can only make a genuine proof *fail* (liveness), never make an invalid one *succeed* (safety). The pinned cryptographic trust inputs are the per-network **Mithril genesis Ed25519 vkey** and — for the Tier-2 ancillary bootstrap only — the pinned **ancillary Ed25519 vkey** (README.md:148; `src/ancillary.rs:32-41`).

## 1. Claims inventory

Journal-field lists below follow the journal-is-the-ABI rule: everything the verdict depends on — trust anchors, claim identifiers, verdict band, and every scoping/assumption field — appears in the journal. The C ABI (`src/ffi.rs`, `SEXTANT_ABI_VERSION = 5`, ffi.rs:46) already defines fixed-width, banded verdict structs; they are the ready-made journal schema and are cited per leg. (README.md:65 still says ABI v4 — stale; ffi.rs is authoritative.)

### Leg 1 — Praos header segment (opcert / VRF / KES / hash links)

- **Entry point:** `chain::verify_segment(blocks: &[B], eta0: &[u8;32]) -> Result<(), ChainError>` — `src/chain.rs:82`. Per-header unit `verify_header` (chain.rs:107): opcert → VRF → KES, in that order.
- **Inputs.** Untrusted: the ledger `[era, block]` CBOR of each block (Babbage=6/Conway=7 only, `src/header.rs:26-29`). Anchor-ish input: `eta0`, the 32-byte epoch nonce for the (single-epoch) segment — itself derivable from verified headers via the nonce primitives (`src/nonce.rs:28-65`: `combine`, `block_nonce_contribution`, `evolve`, `epoch_nonce`, all Blake2b-256), proven across a real 299→300 epoch boundary (README.md:32).
- **Ok proves:** every header decodes strictly (exact CBOR shape, no trailing bytes, header.rs:106-120); each block's `prev_hash` equals its predecessor's Blake2b-256 header hash (chain.rs:87-90); each header's authorship: cold→hot Ed25519 opcert over `hot_vkey ‖ BE64(seq) ‖ BE64(kes_period)` (`src/kes.rs:71-88`), leader VRF ECVRF-ED25519-SHA512-Elligator2 draft-03 against `alpha = Blake2b256(BE64(slot) ‖ eta0)` (`src/vrf.rs:94-152`), and `Sum6Kes` body signature over the raw `header_body` bytes at the header-implied evolution period (kes.rs:118-129, recursion kes.rs:137-164).
- **Assumes (surfaced, not checked):** the supplied `eta0` is the true epoch nonce; and crucially a verified segment is **not** proven canonical — "that rests on the Mithril anchor, a surfaced assumption" (README.md:143). Honest-majority block authorship is what a valid header buys, nothing more.
- **Tier:** a building block (no spend-status tier of its own).
- **Journal fields** (model: `chain_status` flattening at ffi.rs:329-349 + `SextantErrorDetail` ffi.rs:143): `eta0`, block `count`, first block `{hash, number}`, tip block `{hash, number, slot}`, status ∈ {Ok, 200-band ChainError with offending index + inner leaf code (100/110/120 bands)}.

### Leg 2 — Mithril STM certificate chain to genesis (the trust terminus)

- **Entry points** (`src/mithril.rs`, `mithril` feature only):
  - `verify_chain(certs) -> VerifiedChain` — mithril.rs:283. Integrity (recomputed content hash == committed `hash`, mithril.rs:288), linkage (`previous_hash` == parent hash, mithril.rs:295), AVK binding (same-epoch AVK unchanged, or next-epoch AVK == parent's committed `next_aggregate_verification_key` part, mithril.rs:298-308).
  - `verify_genesis(cert, genesis_vkey) -> Result<(), GenesisError>` — mithril.rs:373. Genesis cert, `signed_message == H(protocol_message)` binding (mithril.rs:378), 64-byte Ed25519 signature over the ASCII-hex `signed_message` under the **pinned genesis vkey**, verified on Sextant's own libsodium-strict Ed25519 (`src/ed25519.rs:26`).
  - `verify_standard(cert) -> Result<(), StandardError>` — mithril.rs:468. Message binding, degenerate-threshold refusal (`k==0 || m==0 || phi_f ∉ (0,1)`, mithril.rs:484), DoS caps (`MAX_STM_BLOB_HEX` 4 MiB, `MAX_AVK_LEAVES` 2^24, `MAX_SINGLE_SIGS` 2^16, `MAX_LOTTERY_INDICES` 2^18; mithril.rs:530-545; `guard_stm_bounds` mithril.rs:564-610), then the composed `mithril_stm` primitive: `AggregateSignature::<MithrilMembershipDigest>::verify(signed_message.as_bytes(), &avk, &params)` (mithril.rs:507-522).
  - `verify_chain_anchored(certs, genesis_vkey) -> VerifiedChain` — mithril.rs:666. Composes all three: integrity/linkage/AVK first (so a parameter-weakened forgery never reaches `verify_standard` with attacker-chosen thresholds, mithril.rs:662-664), genesis root, then STM on every rising cert.
- **Inputs.** Untrusted: aggregator certificate JSON, oldest-first, parsed on Sextant's own path (`Certificate::from_json`, mithril.rs:104). Pinned anchor: `genesis_vkey` (32 bytes, per network, reviewed out of band — mithril.rs:371-372).
- **Ok proves:** a hash-linked, AVK-bound certificate chain whose root is signed by the network genesis key and whose every rising certificate carries a valid stake-threshold multi-signature under its own (predecessor-authorized) AVK. The tip's `certified_transactions` accessor (mithril.rs:138-165) yields `{merkle_root, epoch, block_number}` read from the **signed protocol-message parts only** — deliberately not from `signed_entity_type`, which is not covered by `signed_message` and an aggregator could reseal (mithril.rs:129-137). Content hashing is byte-exact to `mithril-common`: `U8F24` `phi_f` fixed-point (mithril.rs:892-894), chrono nanosecond timestamps (mithril.rs:898-900), `ProtocolMessagePartKey` enum-order hashing (mithril.rs:847-867).
- **Assumes:** the pinned genesis key is the network's; Mithril's own security assumption (an adversary below the stake threshold parameterized by `k/m/phi_f` — the parameters themselves are pinned by the cert hash, but their *adequacy* is an external assumption); unknown signed-entity/part-key tags fail closed as deserialization errors (mithril.rs:727, :846).
- **Tier:** the trust terminus every other Mithril-anchored leg cites.
- **Journal fields** (model: ffi 300/310/320 bands, ffi.rs:112-129): `genesis_vkey`, `root_hash`, `tip_hash`, `length`, optional `certified_transactions{merkle_root, epoch, block_number}`, status (with offending cert index on failure).

### Leg 3 — Certified transaction inclusion (MKMapProof / MMR recompute)

- **Entry point:** `inclusion::verify_tx_inclusion(proof_hex, tx_hash: &[u8;32], certified_root: &[u8;32])` — `src/inclusion.rs:412`. Default wasm-safe graph — no blst, no mithril-stm (inclusion.rs:3-8).
- **Inputs.** Untrusted: the aggregator's HEX(JSON) `MKMapProof<BlockRange>` (capped at `MAX_PROOF_HEX` 8 MiB, inclusion.rs:36; MMR size capped 2^40, inclusion.rs:41). Claim: the 32-byte tx hash (appears in the proof as lowercase-hex ASCII leaves, inclusion.rs:404-405). Anchor: `certified_root` — genesis-anchored only when taken from a Leg-2 verified tip cert.
- **Ok proves:** `tx_hash` is a member of the Mithril-certified transaction set with root `certified_root`. Every sub-proof root is recomputed (BLAKE2s-256 MMR, ported with checked arithmetic from ckb-mmr, inclusion.rs:116-315) and bound into the master tree as a `merge("start-end", sub_root)` leaf (inclusion.rs:334-357); stated `inner_root` fields are **never deserialized** (inclusion.rs:75-77).
- **Assumes:** nothing beyond the root's provenance (a Leg-2 assumption). Membership is a monotone "created" predicate trailing tip by ~100 blocks — explicitly not unspent (inclusion.rs:11-18).
- **Tier:** building block for Legs 4/5.
- **Journal fields** (400-band, ffi.rs:131-133): `tx_hash`, `certified_root`, status ∈ {Ok, NotIncluded, RootMismatch, MalformedProof}.

### Leg 4 — Verified UTxO read (Tier 0: `NotEstablished`)

- **Entry point:** `utxo::verify_utxo_read(tx_bytes, out_index, proof_hex, certified_root, block_number) -> VerifiedOutput` — `src/utxo.rs:253`.
- **Inputs.** Untrusted: raw Conway tx-body CBOR (`tx_bytes` — hashed in-function to Blake2b-256, never a provider hash, utxo.rs:29-34,260), the inclusion proof, `out_index`. Anchors: `certified_root` + `block_number` from a Leg-2 tip (echoed as `certified_at`).
- **Ok proves:** the returned `{address, lovelace, datum}` are the authentic on-chain bytes of output `(H, out_index)` of a Mithril-certified transaction, as of `certified_at`. It does **not** prove unspent (utxo.rs:8-27): the return type is pinned to `SpendStatus::NotEstablished` (utxo.rs:269).
- **The tier ladder** lives here — `SpendStatus` (utxo.rs:160-191, `#[non_exhaustive]`, compile-time tripwire test utxo.rs:619-648): `NotEstablished` (Tier 0/1), `CertifiedUnspent{basis: AnchorBasis, through_block, mithril_quorum}` (Tier 2, cryptographic), Tier 3 attested reserved/economic. `AnchorBasis` (utxo.rs:121-131): `StmCertified` vs `AncillarySigned`, uncoercible, dischargeable single-key→quorum via extraction audit (docs/tier2-bootstrap.md:43-65). At the ABI: tier byte 0 / 2 (`SEXTANT_SPEND_CERTIFIED`), economic reserved 3+, basis byte 1/2 (ffi.rs:58-75).
- **Journal fields** (model: `SextantVerifiedOutput`, ffi.rs:191-211): `tx_id`(=Blake2b(tx_bytes)), `out_index`, `certified_root`, `lovelace`, `certified_at`, `address` (or its hash — variable-length; a guest may journal `H(address)` + len), `datum_kind`(0/1/2) + datum hash/bytes-hash, `spend_status = 0` always.

### Leg 5 — Windowed no-spend watch (Tier 1: `WatchedWindow`)

- **Entry point:** `window::verify_watched_window(watch: OutPoint, anchor: &CertifiedTransactions, require_through: u64, blocks, eta0, freshness: Freshness) -> WatchVerdict` — `src/window.rs:368`. Composes Leg 1 (window.rs:382) → per-block body-commitment bind (recomputed `hashAlonzoSegWits`: outer Blake2b-256 over the four raw body-segment hashes, window.rs:88-97; spans from `header.rs:95-104`, hashed **verbatim** — block CBOR is non-canonical) → per-tx spend scan `decode_spends` (inputs key 0 + collateral key 13 are spends; reference inputs key 18 are not; utxo.rs:283-298) with creation check `output_exists` (utxo.rs:449).
- **Inputs.** Untrusted: the block window. Anchors/caller policy: `anchor` (Leg-2 certified `{merkle_root, epoch, block_number}`), `eta0`, `require_through` (hard tip lower bound — closes the truncate-before-the-spend evasion, window.rs:27-31,456-458), `freshness{slot_now, max_lag}` (caller's clock — the guest has none; sans-io by construction, window.rs:211-219 has deliberately no `now`).
- **Verdict (three shapes, `WatchVerdict` window.rs:311-345):**
  - `Unspent{as_of: WatchedTip{anchor_height, as_of_height, as_of_slot}, basis: WatchedWindow(WindowAssumptions)}` — requires gap-free contiguity (window.rs:446-449), creation observed in-window (window.rs:451), `tip ≥ require_through` (window.rs:456), `tip ≤ anchor.block_number` (window.rs:459), fresh tip (window.rs:462).
  - `SpentObserved{at_height, at_slot, spending_txid, region: SpendRegion}` — definite refuse; region `HeaderVouched` by default, upgraded to `MithrilCertified` only by a verified inclusion proof of the spending tx against the certified root (`certify_spend_region`, window.rs:497-508 — height never upgrades a spend, window.rs:289-292).
  - `Stalled{verified_through, reason: StallReason}` — every non-answer (11 reasons, window.rs:226-262); a withheld block collapses to a stall, never a false unspent.
- **Assumes — `WindowAssumptions` (window.rs:171-187), mandatory data, not prose:** `mithril_quorum` — the served chain is the certified one; Sextant verifies headers, links, and the height bound but does **not** bind each served block to the certified tx root and holds no stake distribution for leader eligibility, so a colluding registered producer could serve a valid-header chain omitting a spend (window.rs:174-183; the stated cryptographic closure is a Tier-2 per-block commitment). `data_complete` — gap-free, body-committed run.
- **Journal fields** (model: `SextantWatchVerdict`, ffi.rs:884-919 — adopt nearly verbatim): `kind`(1/2/3), `basis`(=1 WatchedWindow; band 1..=9 cryptographic-with-assumptions, ledger-state reserved in-band, README.md:50/ffi.rs:776-781), `assumptions` bitset (bit0 mithril_quorum, bit1 data_complete; ffi.rs:789-792), `stall_reason`(1..=11), `spend_region`(1/2), `anchor_height`, `as_of_height`, `as_of_slot`, `verified_through`, `spend_at_height`, `spend_at_slot`, `spending_txid` — **plus the inputs**: `watch{tx_id,index}`, `eta0`, `require_through`, `freshness{slot_now,max_lag}`.

### Leg 6 — Tier-2 certified set: bootstrap-verify, follow, membership (`CertifiedUnspent`)

- **Entry points:**
  - `ancillary::verify_ancillary_manifest(manifest_json, ancillary_vkey) -> VerifiedAncillaryManifest` — `src/ancillary.rs:113` (T3-verify). SHA-256 over the sorted `(path ‖ hex-digest)` map, Ed25519 under the pinned per-network ancillary vkey (ancillary.rs:32-41 — a **single IOG key**, the `AncillarySigned` trust class). Verified per-file digests then gate the 909 MB `tables` parse and the `state`-file tip extraction (docs/utxo-hd-format.md:57-113; the tables parser + `parse_tip` live in `tools/snapshot`, outside the trust core).
  - `setfollow::apply_block(set, block, eta0) -> SetTip` — `src/setfollow.rs:64` (T4-follow): Leg-1 header crypto on the single block → `effects::extract_block_effects` (`src/effects.rs:53` — body-commitment bind + per-tx consumed/created with phase-2 validity: valid tx spends key 0 / creates key-1 outputs; invalid tx spends collateral key 13 / creates only the collateral return at index `|outputs|`, effects.rs:9-18,99-129) → `UtxoSet::apply` (`src/utxoset.rs:464` — contiguity, atomic one-transaction mutation, `SpendOfUnknownOutput`/`DuplicateOutput` fail-closed). The forward follow is itself a subset-consistency audit of the ancillary (setfollow.rs:18-28).
  - `UtxoSet::certified_spend_status(&o) -> SpendStatus` — utxoset.rs:426: `CertifiedUnspent{basis, through_block=tip.number, mithril_quorum = tip.number <= anchor_height}` iff the outpoint is a member, the set was anchored at construction (`from_anchor`/`with_store_anchored`, utxoset.rs:328/359 — basis is never a query-time argument), and a tip exists; else `NotEstablished`, never a false positive. `re_anchor` (utxoset.rs:445) monotonically advances the quorum frontier from a Leg-2-verified cert.
  - `UtxoSet::fingerprint() -> [u8;32]` — utxoset.rs:386: SHA-256 over every outpoint's `tx_id ‖ BE-u16 index` in ascending key order — byte-identical to the ancillary `tables` key layout (docs/utxo-hd-format.md:41-54), and the comparison the `AncillarySigned → StmCertified` discharge rests on.
- **Ok proves:** the outpoint is unspent as of `through_block` in a set descending from a certified snapshot S (trust class `basis`) advanced only by header-verified, body-committed, contiguous blocks — covering both pre-S members and window-created outpoints (utxoset.rs:405-425).
- **Assumes:** the anchor basis (single IOG key vs stake quorum — machine-readable, uncoercible); above the certified frontier the window tail is header-vouched only (`mithril_quorum` bit).
- **Journal fields** (model: `SextantSpendStatus`, ffi.rs:228-242): `tier`(0/2), `basis`(1/2), `mithril_quorum`(0/1), `through_block`, plus outpoint, `SnapshotAnchor{tip{number,hash}, basis}` (utxoset.rs:90), certified frontier height, and — for the continuation pattern — set `fingerprint` in/out. **This leg is heliograph's natural state-transition proof:** `journal = {fingerprint_in, tip_in, fingerprint_out, tip_out, eta0(s), n_blocks}` per `apply_block` batch, with `certified_spend_status` a cheap membership read against the proven state.

## 2. Guest-safety analysis (no_std / zkVM)

### 2.1 The default graph is effectively no_std+alloc already

Dependencies (Cargo.toml:43-67): `minicbor` (alloc), `amaru-curve25519-dalek` 3.2 (`default-features=false, u64_backend, alloc`), `sha2` 0.9 / `blake2` 0.9 (`default-features=false`), `serde`/`serde_json` (`default-features=false, alloc` — the no_std configuration). No clock, no fs, no net in any verify path. The only std creep in the default-graph sources (grep-verified across `src/`):

1. `use std::collections::…` — `utxo.rs:36` (BTreeSet), `utxoset.rs:37` (BTreeSet, VecDeque), `inclusion.rs:27` (VecDeque), `effects.rs:20` (BTreeSet), `follow.rs:84` (BTreeMap, VecDeque), `ancillary.rs:23` (BTreeMap). All exist in `alloc::collections` — mechanical swap.
2. `impl std::error::Error for …` — chain.rs:62, header.rs:133, vrf.rs:69, kes.rs:66, inclusion.rs:73, utxo.rs:237, window.rs:65, setfollow.rs:58, ancillary.rs:105 (and mithril.rs ×4). `core::error::Error` is stable (Rust ≥1.81; the crate is edition 2024) — mechanical swap.
3. `ffi.rs:20-21` (`std::ptr`, `std::slice` → `core::`) and the `std::panic::catch_unwind` guard (ffi.rs:279-292) — already cfg-split for wasm32; a guest build simply doesn't need the FFI module at all (the journal replaces it).
4. `String`/`Vec`/`format!` usage (e.g. `inclusion.rs:335` `format!("{start}-{end}")`, mithril hex strings) — all alloc-satisfiable.
5. Test modules use `std::fs` (window.rs:570, setfollow.rs:91-119) — `#[cfg(test)]`, irrelevant.

So Legs 1, 3, 4, 5, 6 (minus ancillary's serde_json, which is already no_std-configured) are no_std-able with a `#![cfg_attr(not(feature="std"), no_std)]` + `extern crate alloc` pass and zero algorithmic change. Determinism notes: no wall clock anywhere (freshness is an input); `serde_json` parsing is deterministic with a compiled-in recursion bound (Cargo.toml:63); the one `f64` in the default graph is absent — `phi_f` appears only under `mithril` (see below; zkVM RISC-V targets emulate IEEE f64 deterministically, and `phi_f_fixed_bits` at mithril.rs:892 is exact power-of-two arithmetic with `round_ties_even`).

### 2.2 The `mithril` feature is the guest blocker — dependency chain, confirmed from the lockfile

`mithril = ["dep:chrono", "dep:mithril-stm"]` (Cargo.toml:41).

- **`chrono` 0.4** (`default-features=false, serde, alloc`, Cargo.toml:67): used only for `DateTime<Utc>` deserialize + `timestamp_nanos_opt()` in the metadata hash (mithril.rs:762-776, :898-900). chrono in this configuration is documented no_std-compatible (the lockfile's `iana-time-zone`/`windows-link` ride the default `clock` feature, which is off). Low risk; fallback is a ~40-line RFC3339→i64-nanos parser, since only parse+nanos are consumed.
- **`mithril-stm` 0.10.5** (`default-features=false, num-integer-backend`): Cargo.lock:1182-1202 shows its resolved dependencies include **`blst` 0.3.16** and **`rayon` 1.12** unconditionally (plus anyhow, ciborium, num-bigint/-integer/-rational, rand_core, serde, subtle, thiserror). Two independent blockers:
  - **blst is C** (built via `cc`, with a `threadpool` dep — Cargo.lock:180-189). It has a `portable` (no-asm) C path and compiles to wasm32 with clang, but for a RISC-V zkVM guest it means cross-compiling C to the guest ISA and losing the ecosystem's accelerated pure-Rust BLS12-381 patches. No pure-Rust backend exists in mithril-stm 0.10.5 — the STM types are built directly on blst types.
  - **rayon requires std threads** — a zkVM guest has none. Whether the *verify* path (vs aggregation) exercises rayon is unresolved, but rayon-core failing to build for a no_std/riscv target kills the compile regardless.
  - Consequence: **Leg 2's `verify_standard` cannot ride mithril-stm in a guest.** Everything else in Leg 2 (content hashing, chain walk, AVK binding, genesis Ed25519, DoS bounds) is Sextant's own pure-Rust code and is guest-clean.

### 2.3 What the STM multi-signature verify mathematically requires

Sextant owns the orchestration up to `AggregateSignature::verify(msg, avk, params)` (mithril.rs:520-522); the composed primitive is Mithril's *concatenation* proof system over **BLS12-381** with a Blake2b-256 Merkle membership commitment (`MithrilMembershipDigest`, mithril.rs:67-70). Per standard certificate the verify comprises (structure per the mithril-stm design; exact call graph to be pinned against 0.10.5 source in the backend note):

1. **Deserialize** the hex(JSON) AVK (`{mt_commitment:{root, nr_leaves}, total_stake}`) and aggregate signature (a vector of single signatures — each `{sigma: G1 point (48 B compressed), indexes: lottery wins, signer_index}` paired with `(verification_key: G2 point (96 B compressed), stake)` — plus a batch Merkle path). Sextant's `guard_stm_bounds` (mithril.rs:564-610) pre-caps leaves ≤2^24, sigs ≤2^16, total indices ≤2^18, per-signer stake ≤ total_stake — these caps also bound guest cycles.
2. **Merkle batch-path verification**: each signer's `(vk, stake)` leaf against the AVK root — Blake2b-256 hashing, depth ≈ log2(registered pools) ≈ 12; pure hashing, guest-cheap.
3. **Lottery eligibility per index**: an `ev` hash evaluation derived from the signature and index, compared `ev < φ(stake/total_stake)` with `φ(w) = 1−(1−phi_f)^w` evaluated **exactly** via big-rational Taylor-series comparison (the `num-integer-backend`: num-bigint/num-rational — pure Rust, no_std-capable). A genuine certificate carries ≥ `k` winning indices; Mithril's published mainnet parameters are `k=2422, m=20973, phi_f=0.20` (confirm current values against the aggregator), so this is thousands of hash+bignum comparisons per certificate.
4. **One aggregated BLS check**: aggregate the σᵢ (G1 additions) and vkᵢ (G2 additions), hash the message to the curve, and verify the aggregate — a pairing-product check (2 Miller loops + final exponentiation). This is the only pairing work per certificate; the group orientation (48 B sigs / 96 B keys ⇒ min-sig, hash-to-G1) and the exact DST must be transcribed from mithril-stm source.
5. **Chain cost**: `verify_chain_anchored` runs one genesis Ed25519 + one STM verify per rising certificate. The `previous_hash` walk to genesis is roughly one certificate per epoch (Mithril mainnet ≈ low hundreds of certificates to date) — so a full from-genesis anchor in-guest is `~N_epochs × (1 pairing check + k lottery evals + Merkle batch)`. With zkVM BLS12-381 precompiles/patches this is tractable; heliograph can also prove the chain walk once and continue from a proven tip (the same continuation pattern as Leg 6).

## 3. Upstream guest-feature sketch (minimal Sextant changes)

1. **`no_std` + alloc pass** (mechanical, default graph): `#![cfg_attr(not(feature = "std"), no_std)]`, `extern crate alloc`, `std::collections→alloc::collections`, `std::error::Error→core::error::Error`, `ffi` module gated behind a `std`/`ffi` feature (guest never builds it). No verify-path logic changes; the existing wasm32 CI leg already proves the graph is socket/clock/fs-free.
2. **STM backend seam**: the entire mithril-stm surface Sextant touches is four types + one call (mithril.rs:59-62, :507-522). Introduce a backend boundary there — feature `mithril` (host: mithril-stm/blst, as today, differential oracle) vs `mithril-guest` (pure-Rust: `bls12_381` (zkcrypto, no_std, has SP1/RISC Zero accelerated forks) + `num-bigint` for the lottery comparison + Sextant-owned wire deserialize of the AVK/signature JSON — the shapes are already partially parsed by `guard_stm_bounds`). The guest backend must be differentially tested against mithril-stm on the same harvested certificate vectors (the discipline the whole repo runs on, README.md:24).
3. **chrono removal or no_std confirmation** for the `mithril` verify path: either pin the `chrono(no_std)` build in CI or replace with an in-crate RFC3339→nanos parser (only `parse_from_rfc3339` + `timestamp_nanos_opt` are consumed, mithril.rs:762-776).
4. **Deterministic input encodings**: already adequate — every entry point takes raw bytes (block CBOR, cert JSON, hex(JSON) proofs) and all DoS caps are compiled-in. The guest should journal input *commitments* where identity matters: the tip/root certificate content hashes (Sextant's own `compute_hash` is the canonical commitment), `certified_root`, `eta0`, and the set `fingerprint` for Tier-2 continuations.
5. **No time/format deps on verify paths**: already true (freshness is caller data; `Display` impls are core-only). The only formatting on a verify path is `format!("{start}-{end}")` for MMR range leaves (inclusion.rs:335) — alloc-safe, deterministic.

## 4. Unresolved / to confirm

- mithril-stm 0.10.5 verify-path internals: exact group orientation, hash-to-curve DST, whether `AggregateSignature::verify` itself uses rayon, and the precise `ev` evaluation — transcribe from source before building the `mithril-guest` backend (this note deliberately does not re-derive them).
- Current preprod/mainnet STM parameters (`k/m/phi_f`) for guest cycle budgeting — read them off a live certificate.
