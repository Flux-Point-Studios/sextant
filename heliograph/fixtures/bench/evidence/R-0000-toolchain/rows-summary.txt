Determinism observation: repeated runs of the identical (ELF, input) pair reproduce
journal bytes exactly, but user_cycles varies by ~155 cycles run-to-run on the golden
paths (e.g. R-0001 197,220,545 vs probe 197,220,700). The verify stage consumes host
entropy (getrandom -> sys_random; blst uses random blinding scalars in aggregate
verification), so cycle counts are entropy-dependent at the margin. Journals are
unaffected. BENCH.md §2.4's run-twice determinism check must compare journals, not
cycle counts, and proving-tier rows should record this variance.

Runtime-features finding (the "rayon question", full narrative in spike README):
mithril-stm 0.10.5 never calls rayon in library code (doc-comment examples only) —
rayon-core never initializes in-guest. The actual thread user on the verify path is
blst's Rust-binding worker pool: std::thread spawn is Unsupported on riscv32im-
risc0-zkvm-elf, first surfacing as a disabled sys_getenv (RUST_MIN_STACK read inside
std::thread::Builder::spawn), then as threadpool-1.8.1's unwrap panic. Fixed with
two additive guest-side Cargo features, zero Sextant/mithril-stm changes:
  risc0-zkvm-platform =2.2.2 features=["sys-getenv"]
  blst 0.3.16 features=["no-threads"]   (blst's documented wasm/serial path)
No upstream ask is needed for the RISC Zero arm.
