runtime quirks discovered (in order):
  1. SP1 v6's native child executor allocates guest memory + trace ring in
     /dev/shm; Docker's default 64 MB shm made it crash with SIGBUS
     (CrashDetails { signal: 7 }). Fix: --shm-size=8g.
  2. First execution attempt panicked in-guest: threadpool-1.8.1
     (blst bindings' da_pool()) called std::thread::spawn, which returns
     io::ErrorKind::Unsupported on SP1's std target -> unwrap panic ->
     execution completes with exit_code=1 and EMPTY public values (SP1 v6
     does not fail the execute() call on guest panic — check exit_code).
     Evidence: R-SP1-E1/first-attempt-panic.log. Fix: blst feature
     "no-threads" via guest-graph feature unification (spike Cargo.toml).
  3. rayon (mithril-stm's unconditional dep) never spawned at runtime:
     mithril-stm 0.10.5 references rayon only in doc comments; the verify
     path is sequential. rayon-core 1.13.0's current-thread fallback for
     Unsupported spawn errors was therefore never exercised.
